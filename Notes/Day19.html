API Integration in React

API Integration is the process of connecting your React application to external services (REST APIs, GraphQL, etc.) to fetch, create, update, or delete data.

📌 Most React apps use Axios or the native Fetch API for HTTP requests.
✅ We'll use JSONPlaceholder (https://jsonplaceholder.typicode.com) – a fake REST API for testing.

CRUD Operations – Overview

CRUD stands for Create, Read, Update, Delete – the four basic operations for persistent storage.

READ – Fetching Data (GET)

import axios from "axios";
import { useState, useEffect } from "react";

function PostsList() {
  const [posts, setPosts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    axios.get("https://jsonplaceholder.typicode.com/posts")
      .then(response => {
        setPosts(response.data);
        setLoading(false);
      })
      .catch(err => {
        setError(err.message);
        setLoading(false);
      });
  }, []);

  if (loading) return <p>Loading posts...</p>;
  if (error) return <p className="text-danger">Error: {error}</p>;
  return (
    <ul>
      {posts.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  );
}

CREATE – Adding Data (POST)

async function createPost(newPost) {
  try {
    const response = await axios.post(
      "https://jsonplaceholder.typicode.com/posts",
      newPost
    );
    console.log("Post created:", response.data);
    // Add to local state
    setPosts(prev => [response.data, ...prev]);
  } catch (error) {
    console.error("Error creating post:", error);
  }
}
✅ The API returns the created post with an ID (usually auto-generated).

UPDATE – Editing Data (PUT)

async function updatePost(id, updatedData) {
  try {
    const response = await axios.put(
      `https://jsonplaceholder.typicode.com/posts/${id}`,
      updatedData
    );
    console.log("Post updated:", response.data);
    // Update in local state
    setPosts(prev => prev.map(post =>
      post.id === id ? response.data : post
    ));
  } catch (error) {
    console.error("Error updating post:", error);
  }
}
🔄 PUT replaces the entire resource. PATCH updates only the fields provided.

DELETE – Removing Data (DELETE)

async function deletePost(id) {
  try {
    await axios.delete(`https://jsonplaceholder.typicode.com/posts/${id}`);
    console.log("Post deleted:", id);
    // Remove from local state
    setPosts(prev => prev.filter(post => post.id !== id));
  } catch (error) {
    console.error("Error deleting post:", error);
  }
}

Context API – Introduction

Context API is a React feature that allows you to share data across the component tree without passing props manually at every level (prop drilling).

🧠 Context is designed for global state like theme, authentication, user data, language, etc.
✅ Three main steps: createContext → Provider → useContext

1. createContext

import { createContext } from "react";

// Create a context object
const UserContext = createContext();

export default UserContext;
📦 This creates a context object that will hold the shared data.

2. Provider – Wrapping the App

import UserContext from "./UserContext";

function App() {
  const [user, setUser] = useState({ name: "John", role: "Admin" });

  return (
    <UserContext.Provider value={{ user, setUser }}>
      <Home />
      <Profile />
    </UserContext.Provider>
  );
}
🔑 The value prop can contain any data (state, functions, objects).

3. useContext – Consuming Context

import { useContext } from "react";
import UserContext from "./UserContext";

function Profile() {
  const { user, setUser } = useContext(UserContext);

  return (
    <div>
      <p>Name: {user.name}</p>
      <p>Role: {user.role}</p>
      <button onClick={() => setUser({ ...user, role: "Editor" })}>
        Change Role
      </button>
    </div>
  );
}
🎯 Any component inside the Provider can access the context using useContext.

Context + API Data

Combine Context API with API calls to manage global application data.

// UserContext.jsx
import { createContext, useState, useEffect } from "react";
import axios from "axios";

export const UserContext = createContext();

export function UserProvider({ children }) {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    axios.get("https://jsonplaceholder.typicode.com/users")
      .then(res => {
        setUsers(res.data);
        setLoading(false);
      });
  }, []);

  return (
    <UserContext.Provider value={{ users, loading, setUsers }}>
      {children}
    </UserContext.Provider>
  );
}

Context API – Best Practices

  • Use for global state – theme, auth, user, language, notifications.
  • Split contexts – separate contexts for different domains (e.g., AuthContext, ThemeContext).
  • Memoize values – wrap the value prop with useMemo to prevent unnecessary re-renders.
  • Custom hooks – create custom hooks like useAuth() to encapsulate context logic.
  • Avoid overuse – for frequent updates, consider state management libraries like Redux or Zustand.
// Custom hook example
function useUser() {
  const context = useContext(UserContext);
  if (!context) throw new Error("useUser must be used within a UserProvider");
  return context;
}

Context API vs Redux

Context APIRedux
Built into ReactExternal library
Simple setupMore boilerplate
Best for small to medium appsBest for large/complex apps
Limited performance optimizationsAdvanced performance tools
No middleware supportMiddleware (thunk, saga)
💡 For most projects, Context API is sufficient. Redux is needed when you have complex state logic and frequent updates.
