Introduction to React JS

React JS is an open-source JavaScript library used for building modern, fast and interactive User Interfaces (UI). It helps developers create dynamic web applications by dividing the user interface into small reusable Components.

Traditional websites reload the complete page whenever data changes. React solves this problem by updating only the required part of the webpage, making applications much faster and smoother.

React follows a Component-Based Architecture and uses Virtual DOM for efficient rendering. Because of these features, React has become one of the most popular frontend technologies used by software companies around the world.

React is a JavaScript Library, not a complete Framework. Its primary purpose is to build beautiful and interactive User Interfaces.

History of React JS

React was created by Jordan Walke, a software engineer at Facebook. It was first used internally by Facebook in 2011 to improve the performance of complex user interfaces.

Seeing its success, Facebook released React as an open-source JavaScript library in 2013. Today React is maintained by Meta along with thousands of contributors from the open-source community.

Property Description
Developer Jordan Walke
Maintained By Meta (Facebook)
Released 2013
Programming Language JavaScript
Current Usage Frontend Development
License Open Source
Popular companies using React include Netflix, Instagram, Airbnb, WhatsApp Web, Dropbox and Microsoft.

Why React JS?

Earlier, developers built websites using HTML, CSS and JavaScript. As applications became larger, maintaining the code became difficult. The same HTML and JavaScript code had to be written repeatedly.

React introduced reusable Components that allow developers to write code once and use it multiple times throughout the application. This reduces development time and improves maintainability.

Without React With React
Repeated Code Reusable Components
Manual DOM Manipulation Virtual DOM
Slow Rendering Fast Rendering
Difficult Maintenance Easy Maintenance
Large Files Small Components
React reduces code duplication and makes large projects easier to manage.

React Architecture

React follows a Component-Based Architecture. Instead of writing the entire webpage in a single HTML file, React divides the application into multiple reusable components. Each component performs a specific task and can be reused anywhere in the application. This makes development faster, code easier to understand, and maintenance much simpler.

Every React application starts from the App Component. The App component acts as the root component and contains all other components like Header, Navbar, Home, Footer, Sidebar, Product Card, etc.

Every UI element in React is represented as an independent Component.
The biggest advantage of React Architecture is Component Reusability.

What is a Single Page Application (SPA)?

SPA stands for Single Page Application. It is a web application that loads only a single HTML page when the application starts. Instead of reloading the entire webpage every time the user clicks on a link, React updates only the required part of the page. This makes the application extremely fast and provides a smooth user experience.

React is mainly used for developing Single Page Applications (SPA).

How SPA Works?

When a user opens a React application, only one HTML page (index.html) is loaded. After that, JavaScript communicates with the server and updates only the required components without refreshing the entire webpage.

What is Virtual DOM?

The Virtual DOM (Document Object Model) is one of the most important features of React. It is a lightweight copy of the Real DOM. Whenever data changes inside a React application, React first updates the Virtual DOM instead of directly modifying the Real DOM. React then compares the old Virtual DOM with the new Virtual DOM using a process called Diffing Algorithm. After finding the changes, React updates only the affected elements inside the Real DOM. This process makes React applications much faster.

Virtual DOM is one of the most frequently asked React interview topics.

Advantages of Virtual DOM

  • Improves Performance.
  • Reduces DOM Manipulation.
  • Fast Rendering.
  • Efficient UI Updates.
  • Smooth User Experience.
  • Less Memory Consumption.
  • Better Scalability.
  • Optimized Rendering Process.
Without Virtual DOM, every UI update would directly manipulate the Real DOM, making applications slower.

Virtual DOM is the main reason why React applications perform faster than traditional JavaScript applications.

What is Node.js?

Node.js is an open-source JavaScript runtime environment that allows developers to execute JavaScript code outside the browser. React itself runs in the browser, but Node.js is required during development to install packages, create projects and run the development server.

Feature Description
Runtime Environment Runs JavaScript outside the browser.
Open Source Free to use.

What is NPM?

NPM (Node Package Manager) is the default package manager of Node.js. It is used to install, update and remove JavaScript libraries and packages. Whenever we create a React project, npm downloads all required dependencies. 

npm install

Installs all dependencies mentioned inside the package.json file. 

npm install react

Installs the React library. 

npm install axios

Installs the Axios package.

npm saves installed packages inside the node_modules folder.

Common NPM Commands

Command Purpose
npm install Install all packages.
npm install package-name Install a package.
npm uninstall package-name Remove a package.
npm update Update installed packages.
npm start Start the application.
npm run dev Run Vite development server.

What is NPX?

NPX (Node Package Execute) is a package execution tool that comes with npm. Unlike npm, npx executes packages directly without installing them globally. It is mainly used to create React projects. 

npx create-react-app myapp
Creates a new React application named myapp.
NPX automatically downloads and executes the required package.

NPM vs NPX

Used frequently. Mainly used once while creating projects.
Slower for one-time execution. Best for one-time execution.

Introduction to JSX

JSX stands for JavaScript XML. It is a syntax extension used in React that allows developers to write HTML-like code inside JavaScript. JSX makes React applications easier to write and understand because developers can create user interfaces using familiar HTML syntax. Although JSX looks like HTML, it is not HTML. JSX is converted into JavaScript by a tool called Babel before the browser executes it.

JSX is one of the most important concepts in React because almost every React component is written using JSX.

Why JSX?

Before JSX was introduced, React developers had to create user interface elements using JavaScript functions such as React.createElement(). Writing large user interfaces using JavaScript functions becomes difficult to read and maintain. JSX solves this problem by allowing developers to write HTML-like code directly inside JavaScript. This makes React applications cleaner, more readable and easier to maintain.

Without JSX With JSX
Long JavaScript Code HTML-like Syntax
Difficult to Read Easy to Read
Complex UI Structure Simple UI Structure
More Boilerplate Code Less Boilerplate Code
Difficult Maintenance Easy Maintenance
JSX improves code readability and developer productivity.

React Without JSX

Without JSX, React elements are created using the React.createElement() method. The syntax is completely JavaScript-based and becomes difficult to understand for large applications. 

const element = React.createElement(

"h1",

null,

"Welcome To React"

);
Output: Welcome To React
Although this syntax is correct, developers generally prefer JSX because it is much cleaner and easier to understand.

React With JSX

Using JSX, the same React element can be written in a much simpler and readable format. 

const element =

<h1>

Welcome To React

</h1>;
Output: Welcome To React
Internally, Babel converts JSX into JavaScript using React.createElement().

Basic JSX Syntax

JSX code is generally written inside the return() statement of a React component. Whenever a component returns JSX, React renders that JSX on the browser screen. 

function App(){

return(

<h1>

Hello React

</h1>

);

}

export default App;
Output: Hello React

Rules of JSX

React follows several important rules while writing JSX. Ignoring these rules will generate compilation errors.

Rule Description
Single Parent Element Every JSX must have one root element.
Proper Closing Tags Every opening tag must have a closing tag.
camelCase Attributes Use className, htmlFor, onClick etc.
JavaScript Expressions Write inside { }
Self Closing Tags Tags like img, br and input must end with /
These JSX rules are among the most frequently asked React interview questions.

Single Parent Element Rule

A React component can return only one parent element. If multiple elements are returned without a common parent, React throws an error.

Incorrect Example
return(

<h1>Hello</h1>

<p>Welcome</p>

);
Error: Adjacent JSX elements must be wrapped in an enclosing tag.
Correct Example
return(

<div>

<h1>Hello</h1>

<p>Welcome</p>

</div>

);
The parent element can be a <div>, <section>, <main>, or even a React Fragment.

React Fragment

A React Fragment allows us to group multiple JSX elements without creating an extra HTML element. Fragments help keep the DOM clean because they do not generate additional tags in the browser.

Using Fragment
import React from "react";

function App(){

return(

<React.Fragment>

<h1>React</h1>

<p>Learning Fragment</p>

</React.Fragment>

);

}
Using Short Syntax
function App(){

return(

<>

<h1>React</h1>

<p>Learning Fragment</p>

</>

);

}
The short syntax (<></>) is the most commonly used Fragment syntax.

JavaScript Expressions in JSX

JSX allows JavaScript expressions to be written inside curly braces { }. Any valid JavaScript expression can be displayed using JSX.

Introduction to Components

A Component is one of the most important building blocks of React. A React application is made up of multiple components. Each component is an independent, reusable piece of UI that performs a specific task. Instead of writing the entire webpage in one file, React divides the application into small reusable components. This makes the application easier to understand, maintain and reuse.

Think of components like LEGO blocks. Small blocks are combined together to build a complete application.

Why Do We Use Components?

Components make application development faster and more organized. Instead of writing the same HTML multiple times, we can create one component and use it anywhere in the application.

Benefit Description
Reusable Write once and use multiple times.
Easy Maintenance Changes are required in only one place.
Readable Code Small files are easier to understand.
Faster Development Components reduce duplicate code.
Better Organization Each file has a specific responsibility.

Most React projects use Default Export.

Default Export Example

A file can contain only one default export. 

function Header(){

return(

<h1>

Welcome

</h1>

);

}

export default Header;

Importing the component: 

import Header from "./Header";
Default export does not require curly braces during import.

Named Export Example

Named exports allow multiple values or components to be exported from the same file. 

export function Header(){

return(

<h1>

Header

</h1>

);

}

Import Statement 

import { Header }

from "./Header";
Named exports must always be imported using curly braces.

Best Practices

  • Use meaningful component names.
  • Always begin component names with a capital letter.
  • Create one component per file.
  • Store components inside a components folder.
  • Keep components small and reusable.
  • Export every component properly.
  • Import components only where required.
  • Avoid writing very large components.

Summary

  • Components are reusable building blocks of React applications.
  • Every React application is made by combining multiple components.
  • Components improve readability, maintainability and code reusability.
  • Components should always start with a capital letter.
  • Components must be exported before they can be imported into another file.
  • Default Export is the most commonly used export method.
  • Nested components help build large applications using smaller UI blocks.
  • Reusable components reduce duplicate code and improve development speed.
